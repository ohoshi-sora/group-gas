# 授業グループワーク管理システム（Google Apps Script）

毎週のグループワークの「クール（時間帯）の申請受付 → 本人確認 → 定員管理 → 班分け → 公開」を、Google フォームと Google スプレッドシートだけで自動化する Google Apps Script（GAS）です。サーバーや外部サービスは使いません。

このリポジトリには、コードが2つ入っています。

| ファイル | 役割 | 使う場面 |
|---|---|---|
| `コード.js` | セットアップ用。フォーム2つとスプレッドシート2つを自動で作る | 科目を作るとき1回だけ |
| `main.js` | 本体。クール分け、班分け、パスワード送信などを動かす | 授業期間中、ずっと |

新しい科目を始めるときの流れは、次の3段階です。

1. `コード.js` で、フォームとスプレッドシートを自動で作る
2. 作られた管理用スプレッドシートに、`main.js` を貼り付ける
3. 自動化メニューからトリガーを登録する

詳しい手順は[セットアップ](#セットアップ)にあります。セットアップ用の `コード.js` を使わず、手作業で一式を作ることもできます（[手作業で作る場合](#手作業で作る場合)）。

## できること

- 学生がフォームでクール（第1〜第4）または BC（ベーシッククラス）を申請し、先着順・定員つきで振り分ける
- 申請時に4桁のパスワードで本人確認する（パスワードは大学のメールアドレス宛に自動送信）
- 授業開始前に、全受講者へ初回パスワードを数日に分けて送信する（MailApp の1日あたりの送信上限への対策）
- クールごとにランダムに班を作り、管理者が確認・修正してから学生用シートに公開する
- 当日参加の学生を、空いている班に追加する
- 週ごとに「フォーム受付開始 → 締切 → 班分け → 公開 → 初期化」をトリガーで自動実行する

## 必要なもの

- Google アカウント（組織のアカウントでも個人のアカウントでも動く見込みです。組織によっては、外部への共有やスクリプトの実行が制限されていることがあります）
- 学生のメールアドレスが `学籍番号@ドメイン` の形で作れること（パスワードの送信先に使います）
- このリポジトリの `コード.js` と `main.js`

## セットアップ

### 手順1 セットアップ用の GAS を作る

1. [script.google.com](https://script.google.com) を開き、「新しいプロジェクト」を作ります。
2. 最初からある `コード.gs` の中身を消し、このリポジトリの `コード.js` の内容をすべて貼り付けて保存します。
3. 左側の歯車（プロジェクトの設定）を開き、「「appsscript.json」マニフェスト ファイルをエディタで表示する」にチェックを入れます。
4. `appsscript.json` を開き、タイムゾーンが `Asia/Tokyo`、実行環境が V8 になっていることを確認します。次の内容です。

   ```json
   {
     "timeZone": "Asia/Tokyo",
     "dependencies": {},
     "exceptionLogging": "STACKDRIVER",
     "runtimeVersion": "V8"
   }
   ```

5. 作ったファイルを置きたい Drive のフォルダへ、このプロジェクトを移動します。初期設定では、このプロジェクトと同じフォルダに一式が作られます。別のフォルダにしたい場合は、手順2で `FOLDER_ID` を指定します。

### 手順2 SETUP を書く

貼り付けたコードの先頭にある `SETUP` を、この科目の値に書き換えます。最低限、次の3か所を確認してください。

1. `COURSE_NAME`: 科目名。`'ここに科目名'` のままだと、実行時にエラーになります。
2. `OVERRIDES`: クール数、チーム数、チームの人数、メールのドメイン（`MAIL_DOMAIN`。初期値のままだとエラーになります）。
3. `SCHEDULE`: 回答の開始・締切、グループ公開の曜日と時刻。

他の大学・研究室で使う場合は、学籍番号の入力規則 `ID_PATTERN` も確認してください。初期値は、`b` か `m` と数字7桁（例: `b2230000`）です。すべての項目は、[SETUP の設定項目](#setup-の設定項目)に書いています。

### 手順3 setupCourse を実行する

1. エディタ上部の関数選択で `setupCourse` を選び、「実行」を押します。
2. 初回は権限の承認画面が出ます。主に、Google ドライブ、Google フォーム、Google スプレッドシートの権限を求められます（表示の文言は環境によって異なります）。
3. 「このアプリは Google で確認されていません」と表示された場合は、「詳細」を開き、「（プロジェクト名）（安全ではないページ）に移動」を選びます。自分で貼り付けたコードなので、この表示は想定どおりです。
4. 実行が終わったら、「実行ログ」を開きます。作られたファイルの URL と、次の手順が表示されます。

途中でエラーが出た場合は、[トラブルシューティング](#トラブルシューティング)を見てください。

### 手順4 フォームを手動で仕上げる

Apps Script の制約で、次の設定は自動では変えられません。クール申請フォームの編集画面で作業します。実行ログの「フォームの手動確認」にも同じ内容が出ます。

1. 「設定 → 回答 → メールアドレスを収集する」を「確認済み」に変更します。作成直後は「回答者からの入力」になっています。「確認済み」にすると、回答者は Google へのログインが必要になります。
2. 同じ画面で、「回答のコピーを回答者に送信」を「常に表示」にします。
3. 説明文の太字を付けます。対象は[太字にする箇所](#太字にする箇所)の一覧を見てください。太字にしなくても動作には影響しません。

### 手順5 本体コードを管理用スプレッドシートに貼り付ける

1. 実行ログに出た「管理用スプレッドシート」を開きます。
2. 「設定」シートを開き、A4 のセルをダブルクリックして編集状態にします。Ctrl+A（全選択）、Ctrl+C（コピー）の順に操作します。セルを選んだだけでコピーすると、先頭と末尾に `"` が付き、文中の `"` が二重になります。必ず、編集状態でコピーしてください。このセルには、本体コードの冒頭にある `const CONFIG = {...};` と同じ形のコードが入っています（[「設定」シートの中身](#設定シートの中身)）。
3. 「拡張機能 → Apps Script」を開きます。
4. 最初からあるコードを消し、手順2でコピーしたコード（`const CONFIG = {...};`）を貼り付けます。
5. その下に、GitHub の `main.js` の142行目以降を貼り付けて、保存します。142行目は、`定数` と書かれたバナーコメントの先頭（`/***`）です。1〜139行目は `main.js` 側の `CONFIG` なので、貼り付けません。
6. スプレッドシートを再読み込みします。メニューに「自動化メニュー」が出れば成功です。
7. 初回にメニューを開くと、権限の承認画面が出ます。手順3と同じ操作で承認します。

必要なシートは手順3で作成済みなので、本体側でシートを作る操作は必要ありません。

### 手順6 トリガーを登録する

管理用スプレッドシートの「自動化メニュー」から、次の2つを順に実行します。

1. 「①フォーム送信 → 送信トリガーを有効化」
2. 「②週次スケジュール → 週次スケジュール登録」

1番目を実行する前に、パスワード再発行フォームの URL を学生に知らせないでください。パスワード再発行フォームは作成直後から受付中ですが、トリガーがないと、回答しても学生にパスワードのメールが届きません。

2番目を実行すると、クール申請フォームが `SCHEDULE` の開始時刻に自動で開きます。締切、班分け、公開、データ初期化も、それぞれの時刻に動きます。

### 手順7 学生共有用スプレッドシートを共有する

初期設定（`STUDENT_SHARING: 'NONE'`）では、学生共有用スプレッドシートは作成者しか開けません。学生に見せる前に、次のどちらかを行います。

- スプレッドシートの共有設定を、手動で変更する
- `SETUP.STUDENT_SHARING` を `'DOMAIN_WITH_LINK'`（組織内でリンクを知っている人）か `'ANYONE_WITH_LINK'`（リンクを知っている全員）にして、手順3の前に設定しておく

いずれも閲覧のみの共有にします。管理用スプレッドシートは、学生と共有しないでください。

### 授業開始前に初回パスワードを配る場合

「自動化メニュー → ③初回パスワード送信」で、授業開始前にパスワードを数日に分けて配布できます。

1. 本体の `CONFIG.INITIAL_PASSWORD_SETTINGS.SEND_SCHEDULE` に、送信する日時を書きます。1回の送信件数が `BATCH_SIZE` なので、受講者数 ÷ `BATCH_SIZE` 回分より多めに日付を書いてください。最後の日時を過ぎても未送信の学生が残る場合、それ以降の送信は予約されず、ログに警告が出るだけです。余分な日付は、害がありません。
2. 「名簿シートを準備」を実行し、作られた「初回パスワード送信」シートの A列に学籍番号、B列に氏名を貼り付けます。
3. 「分割送信を開始（次回分を予約）」を実行します。

1回の送信件数は、`BATCH_SIZE`（初期値 80）と、残りの送信枠 − `KEEP_QUOTA`（初期値 20）の小さいほうです。再発行は、従来どおりパスワードフォームを使います。

## SETUP の設定項目

`SETUP` は、`コード.js` の先頭にあるオブジェクトです。

### 科目名

| 項目 | 内容 |
|---|---|
| `COURSE_NAME` | 科目名。ファイル名、フォームのタイトル、パスワードメールの件名に使われます |

### オーバーライド（本体の既定値を上書きする）

`OVERRIDES` には、本体コードの `CONFIG` と同じ名前で値を書きます。書かなかった項目は、`コード.js` が持つ既定値（本体の `CONFIG` の写し）のままです。この既定値に `OVERRIDES` と自動で決まる値を重ねた、最終的な `CONFIG` が、「設定」シートにコードとして出力されます。

| 項目 | 内容 | 初期値 |
|---|---|---|
| `TOTAL_COOLS` | クール数（3 または 4）。クール申請フォームの選択肢の数も決まります | 3 |
| `TEAMS_PER_COHORT` | 1クールのチーム数 | 7 |
| `MEMBERS_PER_TEAM` | 1チームの人数（最大）。1クールの定員は、チーム数 × 人数です | 4 |
| `MAIL_DOMAIN` | パスワードの送信先ドメイン（学籍番号 + この値）。`@` から書きます。初期値のままだとエラーになります | `'@example.ac.jp'` |
| `SAME_DAY_SETTINGS` | 当日申請の設定。`GENERIC_COOL_PRIORITY` は配置先クールの優先順で、クール数を超える番号は無視されます | `[2, 3, 4]` |

本体の `CONFIG` にある項目なら、ほかも指定できます。`CONFIG` にないキーを書くと、エラーになります。たとえば、次のように書きます。

```js
OVERRIDES: {
  TOTAL_COOLS: 4,
  TEAMS_PER_COHORT: 6,
  MEMBERS_PER_TEAM: 4,
  MAIL_DOMAIN: '@example.ac.jp',
  SAME_DAY_SETTINGS: { GENERIC_COOL_PRIORITY: [3, 4] },

  // 初回パスワードの送信日程（日本時間。先頭から順に使う）
  INITIAL_PASSWORD_SETTINGS: { SEND_SCHEDULE: [{ at: '2026/09/29 12:00' }] }
},
```

次のキーは、セットアップが自動で書くため、`OVERRIDES` に指定するとエラーになります。

- `COOL_FORM_ID`、`PASSWORD_FORM_ID`、`STUDENT_SPREADSHEET_ID`、`STUDENT_ROSTER_SHEET_GID`、`ADMIN_SPREADSHEET_ID`
- `WEEKLY_SCHEDULE` のうち、`coolFormOpen`、`coolFormClose`、`makeRandomGroups`、`groupPublish`、`reset`（次の `SCHEDULE` から自動で決まります）

### 受付スケジュール

`SCHEDULE` の曜日と時刻を書き換えると、次の3つが自動で揃います。文言とスケジュールの食い違いを防ぐためです。

1. フォームの説明文と、回答停止中のメッセージの「いつからいつまで」
2. 本体の週次スケジュール（出力する `CONFIG` の `WEEKLY_SCHEDULE`）
3. グループ分けの実行時刻と、データ初期化の時刻

| 項目 | 内容 | 初期値 |
|---|---|---|
| `OPEN` | 回答開始。`day` は 0=日 1=月 2=火 3=水 4=木 5=金 6=土 | 金 12:15 |
| `CLOSE` | 回答締切 | 木 21:00 |
| `PUBLISH` | グループ公開 | 木 22:00 |
| `MAKE_GROUPS_AFTER_CLOSE_MIN` | グループ分けを、締切の何分後に実行するか | 1 |
| `RESET_BEFORE_OPEN_MIN` | データ初期化を、開始の何分前に実行するか | 25 |

締切が開始より週内で後ろにある場合（たとえば開始が月曜、締切が木曜）は、説明文に「翌週」が付きません。締切が開始と同じか前にある場合は「翌週」が付きます。

### 保存先・共有

| 項目 | 内容 | 初期値 |
|---|---|---|
| `FOLDER_ID` | 作成先の既存フォルダの ID（フォルダの URL の `/folders/` の後ろの文字列）。最優先です | 空 |
| `SAME_FOLDER_AS_SCRIPT` | `true` なら、セットアップ用 GAS と同じフォルダに作ります | `true` |
| `FOLDER_NAME` | マイドライブ直下に、この名前で新しいフォルダを作ります | 空 |
| `STUDENT_SHARING` | 学生共有用スプレッドシートの共有範囲。`'NONE'`、`'DOMAIN_WITH_LINK'`、`'ANYONE_WITH_LINK'` のいずれか | `'NONE'` |

置き場所は、上から順に最初に当てはまるものが使われます。すべて空か `false` の場合は、マイドライブの直下に作られます。

### フォームの文言

`FORM_TEXT` に、フォームのタイトル、説明文、確認メッセージが入っています。文言の中の `{...}` は、実行時に値へ置き換わります。

| 置き換え | 内容 |
|---|---|
| `{COURSE}` | 科目名 |
| `{STUDENT_URL}` | 学生共有用スプレッドシートの URL |
| `{PASSWORD_FORM_URL}` | パスワード再発行フォームの回答用 URL |
| `{COOL_FORM_URL}` | クール申請フォームの回答用 URL |
| `{OPEN_AT}` | 回答開始。例: 金曜日 12:15 |
| `{CLOSE_AT}` | 回答締切。例: 翌週 木曜日 21:00 |
| `{PUBLISH_AT}` | グループ公開。例: 木曜日 22:00 |

文言の中に、科目ごとに変わる内容が書かれている場合は、手動で直してください。たとえば、パスワードの桁数（「4桁の数字」と書いてあります）を `PASSWORD_LENGTH` で変えた場合は、`PASSWORD_HELP` などの文言も合わせて直します。

### フォームの仕様

| 項目 | 内容 | 初期値 |
|---|---|---|
| `ID_PATTERN` | 学籍番号の入力規則（正規表現） | `^[bm]\d{7}$`（`b` か `m` と数字7桁） |
| `ID_PATTERN_HELP` | 入力規則に違反したときのエラー文 | 半角英字 b・数字7桁で入力してください。 |
| `BC_ROUTING` | `true` なら、BC 希望を選んだ人だけが氏名・理由の入力に進み、他の希望は選択後に送信されます。`false` なら、全員が氏名・理由の入力に進みます | `true` |
| `BC_PREF_VALUE` | BC 希望の選択肢の文言 | BC（ベーシック）希望 |

### 質問見出し・シート名（通常は変更しない）

`HEADERS`、`SHEET_NAMES`、`SHEET_ORDER`、`LABELS` は、本体コードの `CONFIG` と同じ値です。ここを変えると、同じ値が出力する `CONFIG` にも書き込まれるので、フォームと本体は一致したままです。

`HEADERS` の各値は、フォームの質問文そのものです。本体コードは、この文言と完全に一致するキーで回答を読みます。

`SHEET_ORDER` は、管理用スプレッドシートのタブの並び順です。`SHEET_NAMES` のキーを左から書き、「設定」シートは `'SETTINGS'` で指定します。初期値では、「設定」は一番右です。

## 作られるもの

### ファイル

| 種類 | 名前 | 内容 |
|---|---|---|
| フォーム | グループワーク・BC申請Form | クール申請フォーム。作成直後は受付停止 |
| フォーム | パスワード再発行Form | パスワード再発行フォーム。作成直後から受付中 |
| スプレッドシート | 科目名_管理用(Form_GAS) | 2つのフォームの回答先。必要なシートと「設定」シートを作成済み。本体コードを貼り付ける |
| スプレッドシート | 科目名_学生共有用 | 「クール分け」「グループ分け」シートを作成済み。学生に見せる |

### 管理用スプレッドシートのシート

| シート | 役割 |
|---|---|
| クール申請フォーム | クール申請フォームの生回答（フォームと自動でリンク） |
| BC参加者 | ベーシッククラス参加者の名簿 |
| 有効申請 | パスワード認証などを通過した申請 |
| 無効申請 | 認証失敗・必須項目不足などの申請 |
| グループ分け確認修正用 | 公開前の班分け案を確認・修正する場所 |
| 当日申請 | 当日申請者の入力・処理結果 |
| パスワードフォーム | パスワード再発行フォームの生回答（フォームと自動でリンク） |
| 学籍・パスワード一覧 | 発行済みパスワードのマスタ |
| パスワードログ | パスワード発行・送信の履歴 |
| 初回パスワード送信 | 授業開始前の初回パスワード配布用の名簿 |
| 設定 | 本体の `const CONFIG = {...};` を、コードとして出力したもの |

### クール申請フォームの質問

| 順 | 質問 | 種類 | 必須 | 補足 |
|---|---|---|---|---|
| 1 | 学籍番号 | 記述式（短文） | はい | `ID_PATTERN` による入力規則つき |
| 2 | パスワード | 記述式（短文） | はい | 説明文に、パスワード再発行フォームの URL |
| 3 | 希望内容 | ラジオボタン | はい | 第1〜第N クール希望と、BC 希望 |
| 4 | （セクション）BCクラス申し込み | | | `BC_ROUTING` が `true` なら、BC 希望の人だけがここへ進む |
| 5 | 氏名 | 記述式（短文） | はい | |
| 6 | ベーシッククラスに参加しようと思った理由を記述してください。 | 記述式（長文） | はい | |
| 7 | わからなかったところ | 記述式（長文） | いいえ | |

フォームの設定は次のとおりです。

- メールアドレスを収集する: オン（作成後に「確認済み」へ変更）
- 回答の編集を許可する、回答を1回に制限する: オフ
- 進行状況バー、質問のシャッフル、結果の概要の表示: オフ
- 別の回答を送信するためのリンクを表示: オン
- 受付: 作成直後は停止。停止中は「回答期間は…です。」のメッセージを表示

### パスワード再発行フォームの質問

| 順 | 質問 | 種類 | 必須 | 補足 |
|---|---|---|---|---|
| 1 | 氏名 | 記述式（短文） | はい | |
| 2 | 学籍番号 | 記述式（短文） | はい | クール申請フォームと同じ入力規則 |

メールアドレスは収集しません。受付は、作成直後から常時受け付けです。本体の週次スケジュールでも、初期設定ではこのフォームを開閉しません。

### 太字にする箇所

フォームの説明文は、Apps Script ではプレーンテキストでしか設定できません。既存のフォームの見た目に合わせるなら、編集画面で次の部分を太字にします。

クール申請フォーム:

- 「回答期間：」「決定方法：」「先着順」「注意事項：」
- 「毎週必ず申請してください。申請したら学生共有スプレッドシートで必ず申請状況を確認してください。」
- 「申請は一度しかすることができません。」
- 「公開スケジュール：」「クール分け：」「グループ分け：」
- 「学生共有スプレッドシート（クール分け・グループ分け表示用）」「パスワード忘れForm」

パスワード再発行フォーム:

- 「学校のメールアドレス宛」
- 「迷惑メールも確認してください。」
- 「以前のパスワードは使用できなくなります。」
- 「グループワーク・BC申請Formから希望クールの申請を行ってください。」

説明文の「・」で始まる行は、本物の箇条書きではなく、ただの文字です。

### 「設定」シートの中身

「設定」シートの A4 のセルに、本体コード冒頭の `const CONFIG = {...};` と同じ形のコードが、1つのセルとして入っています。次の3つを重ねたもので、後ろのものが優先されます。

| 順 | 内容 |
|---|---|
| 1 | `コード.js` が持つ既定値（本体の `CONFIG` の写し） |
| 2 | `SETUP.OVERRIDES` |
| 3 | 自動で決まる値（各 ID、フォームの選択肢・質問見出し、シート名、`SCHEDULE` から作る週次スケジュール） |

本体コードと同じコメントも付いているので、実際に使われる値がそのまま読めます。

本体コードは、このシートを読み込みません。コピーして貼り付けて使います（[手順5](#手順5-本体コードを管理用スプレッドシートに貼り付ける)）。貼り付けたあとに「設定」シートを変えても、本体の動作は変わりません。

出力するコードは、ファイルを作る前に、ダミーの ID で組み立てて確かめます。構文エラーがないか、元の設定と同じ内容かを調べ、食い違っていたら、何も作らずにエラーで止まります。

## 毎週の流れ

初期設定の `SCHEDULE` の場合の動きです。

| 曜日・時刻 | 処理 |
|---|---|
| 金 11:50 | 前週のデータを初期化 |
| 金 12:15 | クール申請フォームの受付開始 |
| 木 21:00 | クール申請フォームの締切 |
| 木 21:01 | 班分け案を「グループ分け確認修正用」シートに出力 |
| 木 22:00 | 班分けを学生共有用シートに公開 |

班分け案の出力から公開までの間に、管理者が「グループ分け確認修正用」シートで班を手直しできます。

## 運用中の操作

管理用スプレッドシートの「自動化メニュー」に、次の項目があります。⭐️は、メニュー上でも印が付いている、よく使う項目です。

| メニュー | 項目 |
|---|---|
| ①フォーム送信 | 送信トリガーを有効化⭐️、送信トリガーを無効化 |
| ②週次スケジュール | 週次スケジュール登録⭐️、週次スケジュール解除、登録状況を表示 |
| ③初回パスワード送信 | 名簿シートを準備、分割送信を開始⭐️、今すぐ1回分を送信、送信状況を表示、分割送信を中止 |
| ④クール分け | 今すぐクール分け・BCを更新 |
| ⑤グループ分け | 確認修正用グループを生成、今すぐ学生に公開、公開予約（設定値より自動設定）、公開予約を確認、公開予約を取消 |
| ⑥フォーム受付 | 受付開始/締切を手動予約、受付予約状況を表示、クール申請フォーム・パスワードフォームを今すぐ開く／閉じる、フォーム予約をすべて取消 |
| ⑦当日申請 | 当日申請シートを準備、当日申請を空き枠へ反映⭐️（1番目）、今すぐ学生に公開⭐️（2番目） |
| ⑧その他 | 必要シートを作成/更新（手作業で作る場合）、全データ初期化（クール申請のみ回答削除） |

「全データ初期化」は、クール申請フォームの回答を削除します。授業期間中に押さないでください。

## 設定を後から変えるとき

作成後に受付時間などを変える場合は、本体コードの `CONFIG` を直接書き換えます。「設定」シートは、作成時の控えとして残しておくだけです。

1. 本体の動作時刻: 本体コードの `CONFIG.WEEKLY_SCHEDULE` を書き換えて保存し、「②週次スケジュール → 週次スケジュール登録」をもう一度実行します。登録し直さないと、予約済みのトリガーは古い時刻のままです。
2. フォームの文言: 説明文と停止中メッセージは、作成時に1回書き込んだだけです。フォームの編集画面で、手動で直します。

`makeRandomGroups`（班分け）と `reset`（データ初期化）は、別の項目です。締切や開始の時刻だけを変えても、連動して動きません。必要なら、これらの項目も一緒に書き換えます。

## 手作業で作る場合

`コード.js` を使わず、フォームとスプレッドシートを自分で作ることもできます。質問文の1文字違いが起きやすいので、慣れていない場合は、セットアップ用の `コード.js` を使うことをおすすめします。

1. 管理用スプレッドシートと学生共有用スプレッドシートを作ります。
2. 2つのフォームを、[作られるもの](#クール申請フォームの質問)の表のとおりに作ります。質問文は、`CONFIG.HEADERS` の文字列と完全に一致させます。「希望内容」の選択肢は、`CONFIG.PREF_VALUE` と一致させます。`TOTAL_COOLS: 3` なら、第4クールは不要です。
3. 両方のフォームで「回答」タブ →「スプレッドシートにリンク」→ 管理用スプレッドシートを選びます。作られた回答シートの名前を、クール申請フォームは `クール申請フォーム`、パスワードフォームは `パスワードフォーム` に変更します。本体は、シート名で、どちらのフォームの回答かを判定します。
4. 管理用スプレッドシートの「拡張機能 → Apps Script」に `main.js` を貼り付けます。
5. 冒頭の `CONFIG` の次の値を書き換えます。

   | 項目 | 入れる値 | 確認する場所 |
   |---|---|---|
   | `COURSE_NAME` | 授業名 | メールの件名と本文に入る |
   | `STUDENT_SPREADSHEET_ID` | 学生共有用スプレッドシートの ID | URL `https://docs.google.com/spreadsheets/d/〇〇〇/edit` の 〇〇〇 |
   | `STUDENT_ROSTER_SHEET_GID` | 学生共有用の「クール分け」にするシートの gid | そのシートを開いたときの URL 末尾 `#gid=〇〇〇`。最初のシートなら通常 `0` |
   | `COOL_FORM_ID` | クール申請フォームの ID | フォーム編集画面の URL `https://docs.google.com/forms/d/〇〇〇/edit` の 〇〇〇 |
   | `PASSWORD_FORM_ID` | パスワードフォームの ID | 同上 |
   | `MAIL_DOMAIN` | 学生メールアドレスの `@` 以降 | 送信先は「学籍番号 + この値」。例: `@example.ac.jp` |

   フォーム ID は編集画面の URL から取ります。学生に配る回答用 URL（`/forms/d/e/...`）に含まれる ID は別物なので、入れると動きません。管理用スプレッドシートの ID は、スクリプトを紐づけたスプレッドシートから自動で取得するので、設定は不要です。

6. 授業に合わせて、クール数（`TOTAL_COOLS`）、班数と人数（`TEAMS_PER_COHORT`、`MEMBERS_PER_TEAM`）、週次スケジュール（`WEEKLY_SCHEDULE`）、初回パスワードの送信日時（`INITIAL_PASSWORD_SETTINGS.SEND_SCHEDULE`）を変更します。
7. スプレッドシートを開き直し、「自動化メニュー」で、⑧その他 →「必要シートを作成/更新」、①フォーム送信 →「送信トリガーを有効化」、②週次スケジュール →「週次スケジュール登録」の順に実行します。

[clasp](https://github.com/google/clasp) を使う場合は、`clasp clone <スクリプトID>` で作られる `.clasp.json` を使って `clasp push` します。スクリプト ID は、Apps Script の「プロジェクトの設定」にあります。`.clasp.json` は `.gitignore` に入っているので、コミットされません。

## 注意と制限

| 項目 | 内容 |
|---|---|
| パスワードの扱い | 「学籍・パスワード一覧」「パスワードログ」シートに、パスワードが入ります。管理用スプレッドシートは学生と共有しないでください |
| メールの送信上限 | MailApp の送信上限は、一般の Google アカウントで1日100通です。受講者が多い場合は、初回パスワードの分割送信を使ってください |
| 説明文の書式 | 太字、箇条書き、リンクの装飾は付きません。URL は文字として入ります |
| メール収集の種類 | オン・オフだけ設定できます。「確認済み」への変更は手動です |
| 回答のコピーの送信 | Apps Script に設定項目が見当たらず、手動で設定します |
| 再実行 | 同じ設定で `setupCourse` を2回実行すると、同名のファイルがもう1セット作られます。上書き・再利用はしません |
| 途中の失敗 | ファイルを作り始めたあとにエラーになっても、作成済みのファイルは自動では削除されません |
| 共有ドライブ | 共有ドライブ内のフォルダを `FOLDER_ID` に指定した場合の動作は、確認していません |
| 本体コードの貼り付け | スプレッドシートに埋め込むスクリプトは、Apps Script の標準の機能だけでは作れず、書き換えられないため、貼り付けは手作業です |

## トラブルシューティング

`setupCourse` の実行時に出るエラーと対処です。

| エラーメッセージ（要約） | 原因と対処 |
|---|---|
| `SETUP.COURSE_NAME に科目名を設定してください。` | `COURSE_NAME` が初期値のままです。科目名を書きます |
| `TOTAL_COOLS は 3 か 4 にしてください。` | クール数は 3 か 4 だけ指定できます |
| `OVERRIDES に自動設定されるキーがあります` | ID 系のキーを `OVERRIDES` に書いています。削除します |
| `OVERRIDES に、本体の CONFIG にないキーがあります` | キー名の綴りの間違いか、本体の `CONFIG` にない項目です。本体の `CONFIG` と同じ名前にします |
| `SETUP.OVERRIDES.MAIL_DOMAIN に、学生のメールアドレスのドメイン…` | `MAIL_DOMAIN` が初期値（`@example.ac.jp`）のままか、`@` で始まっていません。学生のメールアドレスの `@` 以降を書きます |
| `OVERRIDES.WEEKLY_SCHEDULE の … は SCHEDULE から自動設定されます` | 受付時刻を `OVERRIDES` で重ねて指定しています。`SCHEDULE` を変更します |
| `SETUP.SCHEDULE.… は day(0〜6)・hour(0〜23)・minute(0〜59) の整数で…` | 曜日・時・分の範囲を確認します |
| `SETUP.SHEET_ORDER に未知のキーがあります` | `SHEET_NAMES` にないキーを書いています。`'SETTINGS'` 以外は `SHEET_NAMES` のキーです |
| `このスクリプトの親フォルダを取得できませんでした。` | `FOLDER_ID` を指定するか、`SAME_FOLDER_AS_SCRIPT` を `false` にします |
| `出力する CONFIG のコードに構文エラーがあります` / `…設定の内容と一致しません` | 出力処理の不具合です。`CONFIG_DEFAULTS` と `CONFIG_NOTES` を最近変えた場合は、書き間違いがないか確認します |
| `回答シートを特定できませんでした` | フォームの回答先のシートが見つかりません。作成済みのファイルを削除してから、時間を置いて再実行します |

表の最後の1つを除くエラーは、ファイルを作る前に出ます。何も作られていないので、直してそのまま再実行できます。

最後の1つは、ファイルを作り始めたあとに出ます。作成済みのフォーム、スプレッドシート、フォルダが残っているので、Drive で削除してから再実行してください。残したまま再実行すると、同名のファイルが増えます。

## 保守する人へ

`コード.js`（セットアップ用）は、`main.js`（本体）の次の定義を写して持っています。

| `コード.js` 側 | `main.js` 側 |
|---|---|
| `HEADERS`、`LABELS`、`SHEET_NAMES` | `CONFIG.HEADERS`、`CONFIG.LABELS`、`CONFIG.SHEETS`、`CONFIG.STUDENT_SHEETS`、`CONFIG.INITIAL_PASSWORD_SETTINGS.SHEET_NAME` |
| `createAdminManagedSheets_` のシート見出し | `MASTER_HEADERS`、`VALID_HEADERS`、`INVALID_HEADERS`、`PASSWORD_LOG_HEADERS`、`BC_HEADERS`、`SAME_DAY_HEADERS`、`INITIAL_PASSWORD_HEADERS` |
| `createStudentSheets_` のレイアウト | `writeRoster_`、`resetStudentGroupSheet_` |
| `SCHEDULE` から作る5項目 | `CONFIG.WEEKLY_SCHEDULE` |
| `CONFIG_DEFAULTS`（既定値）、`CONFIG_NOTES`（コメント） | `CONFIG` 全体 |

`main.js` の見出しやシート名を変えたときは、`コード.js` も同じ値に直してください。食い違った場合は、本体の「⑧その他 → 必要シートを作成/更新」を実行すると、本体の定義でシートが作り直されます（作成直後は空なので、データは失われません）。

特に、`CONFIG_DEFAULTS` と `CONFIG_NOTES` は、本体の `CONFIG` を丸ごと置き換えるコードの元になっています。`main.js` の `CONFIG` にキーを足した、消した、既定値やコメントを変えたときは、`コード.js` も同じに直し、`CONFIG_TEMPLATE_VERSION` を1つ上げてください。直し忘れると、出力したコードを貼り付けたときに、本体側の変更が失われます。出力したコードの冒頭にテンプレート版が書かれているので、どの版で出力したかを確かめられます。
