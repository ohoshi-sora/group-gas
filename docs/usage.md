# 運用ガイド

このページは、セットアップが終わったあとの、毎週の運用で使うものです。授業を運営する教員や TA が読むことを想定しています。フォームとスプレッドシートの作り方、設定項目、エラーの対処は、[README](../README.md) にあります。

## このページの前提

次の状態になっていることを前提にします。

- 管理用スプレッドシートと学生共有用スプレッドシート、2つのフォームが作られている（[README の手順1〜4](../README.md#セットアップ)）。
- 管理用スプレッドシートに本体コード（`main.js`）が貼り付けてある（[手順5](../README.md#手順5-本体コードを管理用スプレッドシートに貼り付ける)）。
- 「①フォーム送信」と「②週次スケジュール」のトリガーを登録してある（[手順6](../README.md#手順6-トリガーを登録する)）。

トリガーは、登録した人の Google アカウントで動きます。登録したアカウントが使えなくなると、トリガーも止まります。

## 毎週の流れ

初期設定の `SCHEDULE` の場合の動きです。「②週次スケジュール → 週次スケジュール登録」を実行すると、次の処理が時刻どおりに自動で動きます。

| 曜日・時刻 | 処理 |
|---|---|
| 金 11:50 | 前週のデータを初期化 |
| 金 12:15 | クール申請フォームの受付開始 |
| 木 21:00 | クール申請フォームの締切 |
| 木 21:01 | 班分け案を「グループ分け確認修正用」シートに出力 |
| 木 22:00 | 班分けを学生共有用シートに公開 |

管理者が毎週することは、班分け案の確認です。木曜 21:01 に班分け案が出てから、22:00 の公開までの間に、管理用スプレッドシートの「グループ分け確認修正用」シートを開き、班を手直しします。手直しを何もしなければ、班分け案がそのまま公開されます。

公開の時刻を待たずに公開するときは、「⑤グループ分け → 今すぐ学生に公開」を実行します。

## 当日申請

グループ分けを公開したあとに、参加したいと言ってきた学生を、既存の班の空きに追加する機能です。

### 手順

1. 「⑦当日申請 → 当日申請シートを準備」を実行します。管理用スプレッドシートに、「当日申請」シートができます。
2. 「当日申請」シートに、申請者を貼り付けます。使う列は「タイムスタンプ」「学籍番号」「希望内容」の3つです。BC 希望の人は、「BCに参加する学生はBCに参加する理由を書いてください」の列も入れます。この行は「BC参加者」シートにも追加されます（すでに載っている学籍番号は追加しません）。
3. 「⑦当日申請 → 当日申請を空き枠へ反映」を実行します。完了すると、配置した人数などの集計が表示されます。
4. 「当日申請」シートの「処理結果」「配置先」「備考」の列で、一人ひとりの結果を確認します。追加・移動した学籍番号は、「グループ分け確認修正用」シートで色が付きます。
5. 問題がなければ、「⑦当日申請 → 今すぐ学生に公開」を実行します。反映しただけでは、学生には見えません。

メニューの⭐️は、3と5の項目に付いています。この順番で使います。

### どの順で処理されるか

1. BC 希望の人を先に処理します。すでにグループにいる人は BC へ移し、いない人は BC に加えます。
2. BC 以外の人を、次の順で配置します。
   1. 既存の2〜3人の班の空きに入れる。
   2. 3人以上残っていて、空の班があれば、その3人で新しい班を作る。
   3. 新しく作った3人の班に、まだ残っている人を4人目として入れる。
   4. それでも入れない人は、「手動割り当て」の欄に移す。

配置先のクールは、「希望内容」で決まります。

- 「第N クール」を選んでいる人は、そのクールから探し、空きがなければ優先順の次のクールへ進みます。
- 「グループワーク参加希望」のように、クールを選んでいない人は、優先順に探します。優先順は `SAME_DAY_SETTINGS.GENERIC_COOL_PRIORITY` で決まり、初期値は第2→第3→第4です。

同じ学籍番号の申請が複数あるときは、いちばん新しい申請だけを処理します。古い申請は「重複」として飛ばします。

`SAME_DAY_SETTINGS.RESERVED_THREE_PERSON_TEAMS`（初期値 2）は、優先クールごとに、3人の班をいくつ確保しておくかを決めます。3人の班は、当日申請者の受け皿になります。

### 処理結果の意味

| 処理結果 | 意味 |
|---|---|
| 配置済み | 班の空きに入れた |
| BC追加 | BC に加えた |
| BC移動 | すでにいたグループから BC へ移した |
| 手動割り当て | 空きがなく、自動では入れられなかった。「手動割り当て」の欄に移したので、管理者が班を決める |
| 重複 | 同じ学籍番号の新しい申請がある、またはすでにグループか BC にいる |
| 要確認 | 既存のグループ表の中で、同じ学籍番号が重複している。表を見て直す |
| エラー | 学籍番号が空 |

同じ「当日申請」シートに申請者を足して、もう一度反映を実行できます。結果が入っている行は飛ばされるので、二重には配置されません。ただし、「手動割り当て」の人だけは、再実行のたびに、もう一度自動配置を試します。

## 授業開始前に初回パスワードを配る場合

「③初回パスワード送信」で、授業開始前にパスワードを数日に分けて配布できます。

1. 本体の `CONFIG.INITIAL_PASSWORD_SETTINGS.SEND_SCHEDULE` に、送信する日時を書きます。1回の送信件数が `BATCH_SIZE` なので、受講者数 ÷ `BATCH_SIZE` 回分より多めに日付を書いてください。最後の日時を過ぎても未送信の学生が残る場合、それ以降の送信は予約されず、ログに警告が出るだけです。余分な日付は、害がありません。
2. 「名簿シートを準備」を実行し、作られた「初回パスワード送信」シートの A列に学籍番号、B列に氏名を貼り付けます。
3. 「分割送信を開始（次回分を予約）」を実行します。

1回の送信件数は、`BATCH_SIZE`（初期値 80）と、残りの送信枠 − `KEEP_QUOTA`（初期値 20）の小さいほうです。再発行は、従来どおりパスワードフォームを使います。

## メニューの一覧

管理用スプレッドシートの「自動化メニュー」に、次の項目があります。⭐️は、メニュー上でも印が付いている、よく使う項目です。

| メニュー | 項目 |
|---|---|
| ①フォーム送信 | 送信トリガーを有効化⭐️、送信トリガーを無効化 |
| ②週次スケジュール | 週次スケジュール登録⭐️、週次スケジュール解除、登録状況を表示 |
| ③初回パスワード送信 | 名簿シートを準備、分割送信を開始⭐️、今すぐ1回分を送信、送信状況を表示、分割送信を中止 |
| ④クール分け | 今すぐクール分け・BCを更新 |
| ⑤グループ分け | 確認修正用グループを生成、今すぐ学生に公開、公開予約（設定値より自動設定）、公開予約を確認、公開予約を取消 |
| ⑥フォーム受付 | 受付開始/締切を手動予約、受付予約状況を表示、クール申請フォーム・パスワードフォームを今すぐ開く／閉じる、フォーム予約をすべて取消 |
| ⑦当日申請 | 当日申請シートを準備、当日申請を空き枠へ反映⭐️（1番目）、今すぐ学生に公開⭐️（2番目） |
| ⑧その他 | 必要シートを作成/更新（手作業で作る場合）、全データ初期化（クール申請のみ回答削除） |

「全データ初期化」は、クール申請フォームの回答を削除します。授業期間中に押さないでください。

## 設定を後から変えるとき

作成後に受付時間などを変える場合は、本体コードの `CONFIG` を直接書き換えます。「設定」シートは、作成時の控えとして残しておくだけです。

1. 本体の動作時刻: 本体コードの `CONFIG.WEEKLY_SCHEDULE` を書き換えて保存し、「②週次スケジュール → 週次スケジュール登録」をもう一度実行します。登録し直さないと、予約済みのトリガーは古い時刻のままです。
2. フォームの文言: 説明文と停止中メッセージは、作成時に1回書き込んだだけです。フォームの編集画面で、手動で直します。

`makeRandomGroups`（班分け）と `reset`（データ初期化）は、別の項目です。締切や開始の時刻だけを変えても、連動して動きません。必要なら、これらの項目も一緒に書き換えます。

## 管理用スプレッドシートの共有

管理用スプレッドシートは、学生と共有しないでください。「学籍・パスワード一覧」と「パスワードログ」のシートに、学生のパスワードが入っています。

TA などの共同の担当者には、スプレッドシートの共有設定から、その人のアカウントを編集者として個別に追加します。リンクを知っている全員に共有する設定は使わないでください。

学生に見せるのは、学生共有用スプレッドシートだけです。共有範囲は、セットアップ時の `SETUP.STUDENT_SHARING` で決まります（[README の設定項目](../README.md#setup-の設定項目)）。
